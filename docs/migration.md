# Переход на самостоятельный плагин

Применение и обслуживание выполняет владелец из внешнего терминала. Встроенный
раздел удалён из нового ядра; до установки пакета 3D недоступен. `/3d` сохраняет
query и переводит на `/ext/studio3d`. Старый `/api/studio3d` возвращает 404 без
передачи платных запросов новому API.

## Применение

1. Закройте **все** старые окна и вкладки, включая удалённых клиентов. Сохраните
   профиль и IndexedDB. Одного скрытия панели или отмены запросов недостаточно:
   старый JavaScript способен изменить pending после позднего 404.
2. Примените проверенные обновления ядра и окна, вручную перезапустите сервер.
3. Через установщик нового ядра подтвердите установку проверенного чистого
   Git-релиза `studio3d` с точной версией. Рабочая папка разработки не является релизом.
4. Открывайте только обновлённые клиенты. Ранее сохранённое `enabled=true` применяется
   после подтверждённой установки; `false` и отсутствие ключа оставляют пакет выключенным.

Настройки `libraryDir`, `lowDiskGb`, `autoImport`, отдельная библиотека, её UUID,
версии, финансовая история и UUID намерений сохраняются под прежним id.
Копировать данные или преобразовывать журнал вручную не нужно. Известные task ID
продолжают бесплатный опрос; отправка без подтверждения остаётся unknown и не
повторяется автоматически. После выхода прежнего процесса lifetime flock получает
новый runtime. Одновременно запускать два владельца одной библиотеки нельзя.

## Откат ядра

Старый scanner может добавить внешний пакет рядом со встроенной карточкой. Поэтому
до запуска прежнего ядра пакет нужно удалить штатным установщиком **нового** ядра.
Отдельная библиотека, prefs и проверенный export при этом сохраняются.

1. Закройте клиентов. Сохраните наличие и прежнее значение только `plugins.studio3d`.
2. Выключите пакет штатным toggle. Вручную остановите новый сервер.
3. Запустите новый сервер с `enabled=false`: пакет не импортируется, unknown остаётся
   на диске. Штатно удалите незагруженный пакет.
4. Проверьте успешное removal/recovery и отсутствие pending install/update/remove.
   При незавершённой операции сначала выполните штатное recovery; прежнее ядро
   до этого не запускайте.
5. Остановите сервер, верните прежний выпуск и проверьте одну встроенную карточку
   `studio3d`. Восстановите прежнее enabled штатным toggle. Если ключ отсутствовал,
   восстановите его отсутствие только целевым prefs patch при выключенном сервере.

Не переименовывайте managed tree вручную, не удаляйте install journal, библиотеку
или неизвестные оплаты. Журнал и UUID не преобразуются, submitted POST не повторяется.
Активные/unknown задания и открытые файловые потоки блокируют горячую замену пакета;
это не требует стирать данные перед ручным обновлением ядра.
