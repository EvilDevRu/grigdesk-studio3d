# Долговечный журнал заказов 3D

Каждому нажатию соответствует пользовательский UUID. Журнал живёт в
`.jobs/<UUID>/intent.json` отдельно от моделей и содержит исходный запрос,
requestFingerprint, executionFingerprint и дочерние позиции. Канонизация
сортирует ключи по кодовым точкам, сохраняет строки/порядок массивов и отвергает
неконечные числа. Она не применяет текущие правила каталога к replay.

Reserve сериализуется по UUID. Совпадающий fingerprint возвращает прежнюю запись,
различающийся даёт idempotency_conflict. Library UUID проверяется перед поиском
ключа. Getter возвращает копию, update изменяет отдельный снимок под lock. Cache
обновляется только после fsync записи. Одно начальное чтение разделяется всеми
ключами: медленное соседнее чтение не откатывает уже записанное намерение.

JSON имеет закрытую schema и предел 16 МиБ. Symlink, подмена inode, неверный UUID
и файловые ссылки payload вне собственных snapshots запрещены. Ошибка до durable
публикации не меняет старую запись. Ошибка после fsync оставляет новое состояние
доступным recovery. Терминальные записи и ключи автоматически не удаляются.

Identity проекций выделяется до записи журнала под allocation/seq locks, без
создания папок. Журнал сохраняет полные шаблоны модели и каждой версии. После его
fsync материализация создаёт именно эти ID; повтор сохраняет уже обновлённую
версию того же intent/child. Recovery может закончить папку без version.json.
Неподтверждённые планы занимают seq только в памяти; отказ записи их освобождает.

Дочерняя позиция может содержать private `actualSource` и `chargedAt`. Эти optional
поля совместимы с прежними записями и проходят закрытую schema; ключ доступа и его
отпечаток не выдаются через DTO. Изменения суммы сливаются под lock позиции: известный
receipt из usage имеет приоритет над отсутствующим или поздним значением poll.
