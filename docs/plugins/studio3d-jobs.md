# Выполнение заказов 3D

Заказ принимается после проверки цены и сохранения независимых входов. Durable
намерение содержит все дочерние позиции, их параметры, плановые ID моделей и версий.
Проекции восстанавливаются из него. Одновременные запросы одного UUID объединяются;
после удаления модели повтор возвращает tombstone, не создаёт платный заказ.

Перед POST worker записывает `submitting` и синхронно проверяет допуск библиотеки,
доступ исходного аккаунта, актуальную цену и ревизии открытых снимков. Асинхронная
подготовка не предоставляет бессрочного допуска. Изменённая цена требует нового
подтверждения с новым UUID; исходное нажатие остаётся в журнале.

Неопределённая отправка остаётся `unknown` без автоматического POST. История даёт
кандидатов, которые человек связывает отдельным действием по `intentId` и `childId`.
`close-unknown` снимает локальный резерв, сохраняет `unresolved` и неизвестный расход;
это действие не отменяет облачный заказ и не обещает возврат. Поздний reconcile
разрешён, одну облачную задачу нельзя присвоить двум детям.

Баланс API уже исключает frozen: второй раз его вычитать нельзя. Локальные отправки
удерживают оценку до отражения списания в available либо терминального исхода.
Оценка, фактическое списание, подтверждённый возврат и неизвестная оплата хранятся
раздельно. Удаление модели не удаляет финансовый журнал. Успех с ошибкой скачивания
даёт бесплатное повторное скачивание той же задачи, а не платную генерацию.

Пачка сохраняет полный снимок всех строк до создания их проекций. UUID строк
детерминированы из UUID пачки, порядок отправки восстанавливается из снимка.
Неизвестный исход приостанавливает следующие неотправленные строки. Клипы имеют
независимые childId и значения; ошибка одного клипа не меняет остальные.

Опрос и скачивание разделены, одновременно скачиваются максимум два результата.
Остановка worker отменяет его бесплатные чтения, CDN и локальный дочерний процесс;
уже отправленный платный POST сохраняет исход. Терминальные входы удаляются через
семь дней без активного lease, uploads — отдельно. Intent и UUID сохраняются всегда;
после GC retry получает объяснение о сроке хранения входов.

История списаний связывает сумму только по точным task ID, исполнителю и сохранённому
аккаунту. Подтверждённый receipt записывается в intent до проекции модели; неизвестная
отправка без task ID не связывается автоматически. Источник суммы и время списания
сохраняются отдельно от оценки. Поздний poll с отсутствующей стоимостью не стирает
receipt, а возврат меняет состояние только при подтверждении. Неделя использует время
списания при его наличии и остаётся сводкой по известным заказам.

State учитывает ещё не отражённые локальные резервы текущего аккаунта поверх
кешированного баланса поставщика. Отражённый frozen не вычитается повторно.
Для отображения берётся actual вместо оценки, когда receipt уже известен.
Reserved не увеличивает число неизвестных списаний.

## Отмена и восстановление проекций

close-unknown также отменяет prepared-позицию до POST: failed/unpaid без облачного
заказа. Сутки waitingSince закрывают ожидание денег с причиной
«Не хватило средств в течение суток». После трёх пропусков poll принятую позицию
можно оставить unresolved; она перестаёт занимать пул, оплата остаётся неизвестной.

Resume сверяет все записи журнала с версиями. Совпадающий patch не меняет timestamp
и не пишет JSON; отставшая проекция восстанавливается. Переход submitting→unknown
проверяется по актуальному child под intent lock, поэтому сохранённый task ID не
откатывается устаревшим снимком. Ошибка одного child не останавливает соседние записи;
version_not_found означает удалённую проекцию и не восстанавливает удалённую версию.

Баланс worker разделяет по аккаунту на 30 секунд, включая одно общее обещание чтения.
Неизменённые waitReason и другие поля не увеличивают revision и не вызывают fsync.
Частое studio-progress передаёт status вместе с числом прогресса и ETA.

## Терминальные уведомления

Live-уведомление ready отправляется после публикации файлов, durable версии и intent;
failed — после сохранения терминального отказа. Доставка не участвует в денежной
транзакции и не запускает повторный POST. Один projection module строит live и
восстанавливаемый снимок последних 24 часов. UUID библиотеки, intent и child входят
в dedupKey; тема модели позволяет снять её уведомления при удалении. Подробности и
защита от поздней прежней библиотеки описаны в [API и жизненном цикле](studio3d-server.md).
