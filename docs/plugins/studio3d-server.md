# API и жизненный цикл 3D

Ручки `/api/ext/studio3d` требуют общей авторизации и включённого плагина. Создание,
платный повтор, запуск пачки и ручное решение unknown дополнительно требуют сессии
человека. Viewer token не заменяет авторизацию. JSON тела имеют закрытые схемы:
массив вместо строки, лишнее поле и неявное приведение числа отклоняются.

Библиотека закрепляется до запуска worker. Выключенный startup не создаёт её и
не читает облако. Включение выполняет prepare, запись prefs, синхронный commit и
запуск lifecycle. Отказ записи откатывает подготовленные ресурсы. Смена папки
отклоняется при активных и unknown заказах или файловых leases. Абсолютный путь,
включая несуществующего потомка symlink, проверяется против канонических системных
хранилищ до создания каталога. Disable закрывает новый допуск; уже принятые заказы
продолжаются. После старта с выключенным плагином восстановление ждёт включения.

История обновляется и при выключенном автоимпорте: первое обновление через минуту,
следующие через 15 минут. Смена настроек останавливает прежний importer и timer.
Баланс хранится минуту по снимку аккаунта. История передаёт подтверждённые расходы
журналу до выдачи недельной сводки; сумма удерживается до подтверждённого debit.

Uploads требуют `libraryId` первым полем multipart. Изображения ограничены 20 МиБ,
64 мегапикселями и настоящим decode; модели — 150 МиБ и проверкой контейнера. OBJ,
STL, FBX и splat проверяются целиком с пределами размера, глубины, записей и времени.
GLB анализируется отдельным ограниченным процессом. Draco, KTX2 и внешние ресурсы
для импорта отклоняются с причиной. GLTF доступен для просмотра соседних файлов.
Превью принимает настоящие PNG/WebP до 5 МиБ; замена удаляет прежнее превью.

Файлы выдаются с MIME, SHA ETag, HEAD, Range, suffix и If-Range с проверенного
дескриптора. Поток не владеет заимствованным fd копирования: ошибка сохраняет
первоначальную причину, а FileHandle закрывается единственным владельцем.
Сохранение требует доверенного репозитория проекта и актуального SHA при замене.

Viewer resolver получает текущие корни документов, scope чата или «Кода», проектов
и библиотеки. Токен ограничен часом и главным inode; каждый запрос снова проверяет
scope. Потеря области, смена файла, disable и смена библиотеки отзывают доступ.
Для GLTF разрешены только ограниченные embedded data и относительные соседние
bin/PNG/JPEG/WebP. CDN, абсолютные пути и decoder URLs через viewer не читаются.

Проверки: `studio3d-api`, `studio3d-formats`, `studio3d-safe-path`, `plugins-nav`,
`code-*`, `media-storage`, `media-plan-tasks` и изолированный `app-boot-smoke`.

Проверка сессии человека использует шаблон routeOptions.url, поэтому кодирование буквы
пути не открывает платные ручки CLI-токену. OnReady запускает открытие библиотеки в фоне;
медленный start не держит готовность всего Fastify. Ошибка старта делает недоступным
только раздел. Route bodyLimit превью совпадает с проверкой 5 МиБ, а не общим 1 МиБ.

Сервер плагина получает prefix и узкие сервисы через options/core SDK, не через
скрытые decorators приложения. DTO files/viewer строятся от options.prefix.
Library запрещена внутри заменяемого plugin tree/ESM generation и вокруг них;
проверка lexical/canonical пересечений предшествует mkdir/marker/lock.
Lifetime flock сохраняется до освобождения библиотеки. Синхронный assertOwnerNow
проверяет то же владение непосредственно перед платным POST.
После disable принятые jobs завершаются; idle library освобождается под admission
lock после повторной проверки поколения и отсутствия файловых leases. Unknown
удерживает библиотеку и блокирует замену. onClose закрывает admission, отменяет
history/importer/analysis и ждёт jobs.stop()/library.close() до удаления ESM-копии.


Entry — обычная async функция SDK, без fastify-plugin и повторного prefix.
Настройки по умолчанию берутся из metadata, проекты — из `core.project/listProjects`
с сохранением title/archivedAt и missing404; документы используются только через
публичные core методы. Low-level verified fd проверки остаются в локальном reader.

Prepare получает AbortSignal, проверяет отмену на await границах, а поздний rollback
освобождает только новый context. Commit после abort запрещён. OnReady при первом
выключенном load не захватывает библиотеку; первый on запускается afterCommit без
дублирующего onEnable. Scope анализа создаётся отдельно для каждого context;
при cleanup его abort предшествует ожиданию jobs/importer, затем ждутся child/fd
и lifetime flock. Отсутствующий или подменённый worker отвергается до открытия библиотеки.

GET и HEAD файлов зарегистрированы явно с общим Range/ETag handler: HEAD возвращает
длину выбранного диапазона и нулевое body. Response lease удерживает библиотеку до
завершения stream; новый read сериализован с prepare/commit под admission lock.
Настоящая C loader fixture проверяет prefix, multipart, бинарные bytes, auth,
settings timeout, flock и удаление ESM generation после child.close. Эта fixture
не является установленным packaged выпуском; installer/export приёмка выполняется отдельно.

## Серверные уведомления

`lifecycle.notifications(signal)` восстанавливает терминальные уведомления через
общий collector ядра. Он читает только массив `jobs.tasks()` текущей библиотеки,
без HTTP `/tasks`, history или importer. Одна локальная проекция используется для
snapshot и live: ready/failed за последние 24 часа, максимум 500 новых строк в
порядке jobs. Идентификатор — `studio-${versionId}`, тема — `model:${modelId}`,
dedupKey — `${libraryId}:${intentId}:${childId}:${status}`. Заголовки сразу содержат
ru/en; причина отказа сохраняется как данные поставщика, ограниченные 2000 символами.

Ready публикуется после durable сохранения результата, файла и финансовой проекции.
Failed отправляется после долговечной записи терминального перехода. Ошибка доставки
не меняет стоимость или состояние заказа: тот же результат восстановится snapshot.
Повторный tick без перехода не создаёт новое live-событие. Удаление модели отправляет
`dismiss-topic` для её темы, сохраняя финансовый журнал.

Снимок фиксирует library UUID и generation перед await; после него повторяет identity
и AbortSignal проверки. Поздний ответ или отказ прежней библиотеки не показывает тост
новой. Действующая ошибка чтения передаётся общему collector для изоляции источника.
Fixture-проверки используют настоящий core/loader/collector и fake provider; они
не являются приёмкой установленного packaged выпуска или реальной платной операции.


Параметры открытия панели используют канонические `model` и `version`, как generic
panel intent и query `/ext/studio3d?model=…&version=…`. В notification params нет
полей `modelId`/`versionId`: это имена task DTO, а не вход панели. Exact params
проверяются из durable intent/version, snapshot и live совпадают.
